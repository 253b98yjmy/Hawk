# 06. 品質保証、性能目標、マイルストーン

## 1. テスト

| 種類 | 対象 | 方法 |
|---|---|---|
| 単体テスト | base、URL、PSL、HTTP パーサ、Cookie、CSS の値、フィルタの照合 | 自作の小さなテスト基盤（`tests/hk_test.h`）。`ctest` で実行 |
| HTML パーサ | トークナイザ、ツリー構築 | **html5lib-tests**（MIT ライセンス）を全件通す。スクリプト無効のケースを対象にする |
| CSS パーサ | 構文、セレクタ | 自作のケースと、WPT（Web Platform Tests）の解析系テストの一部 |
| レイアウトと描画 | 見た目 | **参照テスト**：テストの HTML と参照用の HTML を両方 Hawk で描画し、画素を比較する。WPT の reftest から、対応範囲のものを選んで使う |
| 実サイトの回帰 | 対象サイト（README 参照） | 保存したページ一式（`bench/corpus/`）を描画して、前回の結果と比較する。差があれば人が確認する |
| ブロッカー | 照合結果 | 「URL・種類・トップレベルのサイト → 期待する判定」の表を用意して検証する。uBO の挙動を手で確認して作る |

## 2. ファジング

- MSVC（または clang-cl）の libFuzzer と ASan を使う（`scripts\build.cmd fuzz`）。対象ごとに、入口となる関数 1 つを用意する（`fuzz/`）。
- **対象**：HTML のトークナイザとツリー構築、CSS パーサ、URL パーサ、HTTP の応答パーサ、chunked の解析、gzip の展開、文字コードの変換、フィルタのパーサとコンパイラ、filters.bin の読み込み、正規表現、Cookie の解析、`srcset` の解析。
- **初期コーパス**：html5lib-tests、実サイトから保存したページ、フィルタリスト。
- ローカルで定期的に実行する。CI（`.github/workflows/ci.yml`）では、main への push と pull request のたびに、各ターゲットを 60 秒ずつ実行する。

## 2.1 CI

GitHub Actions の `windows-latest` で、次の 3 つのジョブを並行して実行する。

| ジョブ | 内容 |
|---|---|
| `test (debug)` | ASan 付きでビルドし、単体テストと起動テストを実行 |
| `test (release)` | LTO 付きでビルドし、テストを実行したあと、起動時間とメモリをログに出力 |
| `fuzz` | ファジング用にビルドし、各ターゲットを 60 秒ずつ実行。クラッシュした入力は成果物（artifact）として保存 |

## 3. 性能目標

| 指標 | 目標 | 計測方法 |
|---|---|---|
| 起動から操作可能まで | 100 ms 以内 | `QueryPerformanceCounter` で計測した値をログに出力 |
| 空白ページでのメモリ（Private Bytes） | 15 MB 以下 | `GetProcessMemoryInfo` の `PrivateUsage` |
| Wikipedia 日本語版「日本」の記事を表示 | 40 MB 以下、表示まで 300 ms 以内（キャッシュ済みの場合） | 保存したページで計測 |
| 典型的なページのタブを 1 つ追加 | 5〜15 MB 増 | |
| 休止状態のタブ | 1 タブあたり 100 KB 以下 | |
| スクロール | 60 fps を維持（1 フレームあたり 16 ms 以内） | フレーム時間を記録 |
| アイドル時の CPU 使用率 | 0%（タイマーで定期的に起きない） | |
| バイナリサイズ | 3 MB 未満 | |

- `bench/` に、保存したページ一式の、解析・スタイル計算・レイアウト・描画の各段階の時間と、最大メモリ量を計測するプログラムを置く。結果は CSV で残し、性能の後退を検出する。
- `hawk:about` で、モジュールごとのメモリ使用量を表示する（01 章のアリーナから集計）。

## 4. マイルストーン（受け入れ基準つき）

| 段階 | 内容 | 受け入れ基準 |
|---|---|---|
| **M0 土台** | CMake の構成、base（アリーナ、文字列、ハッシュ表、アトム）、ウィンドウの表示、テスト基盤、ファジング用の構成 | 空のウィンドウが開く。単体テストが CI で通る |
| **M1 取得と解析** | URL、PSL、DNS、SChannel、HTTP/1.1、gzip、文字コード判定、HTML パーサ（完全版）、DOM、テキストだけを順に描画、ブロッカーの区分 A（ホスト名の照合） | html5lib-tests をすべて通す。Wikipedia の本文がテキストとして読める。リストのホスト名で遮断できる |
| **M2 CSS の基本** | CSS パーサ、カスケード、計算済みスタイル、ブロック整形とインライン整形、DirectWrite での描画、ラスタライザ、スクロール、リンク、戻る・進む | Wikipedia と Hacker News が、作者の CSS で読める見た目になる |
| **M3 実用の最低限** | 画像（WIC、遅延読み込み、縮小しながら展開）、float、position、table、フォーム（単一行の入力、IME）、タブ、ブロッカーの全構文（ネットワーク）と filters.bin、Cookie、HTTP キャッシュ、HTTPS のみモード | DuckDuckGo の HTML 版で検索できる。既定のリストで広告とトラッカーを遮断できる。日本語を入力できる |
| **M4 日常で使える** | Flexbox、要素内のスクロール、要素の非表示ブロッカー、`textarea`、ページ内検索、`hawk:` の内部ページ一式、履歴、ブックマーク、セッションの復元、タブの段階的な破棄、ダウンロード | 対象サイトをすべて実用的に閲覧できる。3 節の性能目標を満たす |
| **M5 完成度の向上** | SVG の一部、`:has()`、`box-shadow`、`transform: translate`、`multipart` での送信、`@layer`、配布用のインストーラ | 主要なニュースサイトやブログの見た目の崩れが小さい |
| **M6 以降** | Grid、Web フォント（WOFF2 / Brotli）、DNS over HTTPS、HTTP/2、拡張セレクタ（`:has-text()` など）、Linux 版 | 必要に応じて優先順位を決める |

## 5. 開発の進め方

- 各マイルストーンの最初に、そのマイルストーンで使う仕様の章を読んでおく（例：M1 なら WHATWG HTML の「Parsing HTML documents」）。
- 新しいパーサを書いたら、**同じ変更でファジング用の入口も追加する**。
- 実サイトの表示崩れは、最小の再現 HTML に縮めてから参照テストとして追加し、それから直す。
- 性能を後退させる変更は、理由と計測値を変更の説明に書く。
