# 04. コンテンツブロッカー

uBlock Origin（uBO）の**仕組みを参考に自作する**。uBO のコードは GPLv3 なので流用しない。
フィルタの構文は、EasyList（Adblock Plus 形式）と uBO の拡張構文のうち、JS がない環境で意味のあるものに対応する。

## 1. 対応する構文

### 1.1 ネットワークフィルタ

| 構文 | 意味 | 対応 |
|---|---|---|
| `\|\|example.com^` | ドメインとそのサブドメインに一致 | ○ |
| `\|https://` / `.js\|` | URL の先頭 / 末尾に一致 | ○ |
| `*` | 任意の文字列 | ○ |
| `^` | 区切り文字（英数字と `_-.%` 以外の文字、または URL の末尾） | ○ |
| `/regex/` | 正規表現 | △（9 節の部分集合のみ。対応外の表現を含むフィルタは捨てて記録する） |
| `@@` | 例外 | ○ |
| `!`、`[Adblock Plus ...]` | コメント | ○ |
| `!#if` / `!#endif`、`!#include` | 条件分岐 / 取り込み | ○（`!#if` は、`env_windows`、`cap_html_filtering` などを Hawk の値で評価する） |

### 1.2 ネットワークフィルタのオプション

| オプション | 対応 | 備考 |
|---|---|---|
| `$third-party` / `$3p`、`$first-party` / `$1p`、`~third-party` | ○ | eTLD+1 で判定する（02 章の PSL） |
| `$image`、`$stylesheet` / `$css`、`$font`、`$document` / `$doc`、`$other`、`$all` | ○ | |
| `$script`、`$xhr`、`$subdocument` / `$frame`、`$media`、`$websocket`、`$ping`、`$popup` | — | そもそもリクエストが発生しないので、そのフィルタ自体を捨てる |
| `$domain=` / `$from=`、`$to=`、`$denyallow=` | ○ | |
| `$important` | ○ | |
| `$match-case` | ○ | |
| `$badfilter` | ○ | 一致するフィルタを無効化する |
| `$removeparam=`、`$removeparam=/re/` | ○ | クエリ文字列から削除する |
| `$redirect=`、`$redirect-rule=` | △ | 遮断として扱う（差し替え用のリソースは JS 用なので不要） |
| `$csp`、`$permissions`、`$header=`、`$replace=` | — | 捨てる |
| `$generichide` / `$ghide`、`$elemhide` / `$ehide`、`$specifichide` / `$shide` | ○ | 要素非表示の例外として使う |

### 1.3 要素の非表示（コスメティックフィルタ）

| 構文 | 意味 | 対応 |
|---|---|---|
| `##.ad` | 全サイト共通の非表示 | ○ |
| `example.com##.ad`、`example.*##.ad`、`~example.com##.ad` | サイトを指定した非表示 | ○ |
| `#@#.ad` | 例外 | ○ |
| `##.x:style(...)` / `#$#` | スタイルの注入 | ○（CSS エンジンを持っているので簡単に対応できる） |
| `#?#` / `:has()`、`:has-text()`、`:upward()`、`:remove()`、`:matches-css()` | 拡張セレクタ | `:has()` は M5、`:has-text()` と `:upward()` は M6、その他は捨てる |
| `##^.ad`（uBO の HTML フィルタ） | パース時に要素を取り除く | ○（ツリー構築の段階で要素を捨てる） |
| `##+js(...)` | スクリプトの注入 | — 捨てる |

## 2. 全体構成

```
[リスト取得（I/O スレッド）] → テキスト → パーサ → 正規化したフィルタ
     → コンパイラ → バイナリスナップショット（filters.bin）
[起動時] filters.bin を MapViewOfFile で読み込み（読み取り専用）
     → ネットワーク照合器（ローダから呼ぶ）
     → 要素非表示の生成器（パース完了時に呼ぶ）→ user origin のスタイルシート
```

## 3. ネットワーク照合

### 3.1 URL の前処理

1. 照合用の文字列を作る：`scheme://host/path?query` を小文字にする（`$match-case` 用に、元の文字列も保持する）。
2. トークンに分割する：英数字と `%` の連続（2 文字以上）をトークンとし、32 ビットのハッシュ（FNV-1a）を計算する。最大 64 個まで。
3. 次の値を求める：ホスト名、そのドメイン部分の列、eTLD+1、リクエストの種類、サードパーティかどうか（トップレベルの eTLD+1 と比較）。

### 3.2 判定の手順

```
1. 結果キャッシュを引く（キー：URL のハッシュ・種類・サードパーティかどうか。LRU で 2048 件）
2. $important の遮断フィルタに一致したら → 遮断（例外は見ない）
3. 遮断フィルタに一致しなければ → 許可
4. 一致した場合、例外フィルタ（@@）に一致すれば → 許可、しなければ → 遮断
5. 許可された場合 → $removeparam を適用して URL を書き換える
```

- 種類が `document` で遮断された場合は、「Hawk がこのページを遮断しました」というページを表示する。そこから「一度だけ開く」「このサイトでは無効にする」を選べるようにする。
- **サイトごとの無効化**（ユーザー設定）：そのトップレベルサイトでは、すべての照合を飛ばす。

### 3.3 データ構造（照合の速さを決める部分）

フィルタを、形によって 4 つの区分に振り分ける。

| 区分 | 対象 | 構造 | 照合方法 |
|---|---|---|---|
| A. ホスト名のみ | `\|\|host^`（オプションなし、または種類・サードパーティの指定だけ） | 64 ビットのホスト名ハッシュを入れたオープンアドレス法のハッシュ表 | ホスト名を 1 階層ずつ短くしながら引く（最大 10 回） |
| B. トークン索引 | 上記以外で、目印になるトークンを持つもの | トークンのハッシュ → フィルタ列の、オープンアドレス法のハッシュ表 | URL のトークンごとに引き、候補だけをパターン照合する |
| C. トークンなし | `*` だけのもの、短すぎるものなど | 線形のリスト | 常に照合する（件数が少ないことを、コンパイル時に警告で確認する） |
| D. 正規表現 | `/re/` | 区分 B のトークン（正規表現の中の固定文字列から抽出）に紐付ける | 候補になったときだけ正規表現を評価する |

- **目印にするトークンの選び方**：フィルタのパターン中のトークンのうち、全フィルタを通して出現回数が最も少ないものを選ぶ。uBO と同じ考え方。`http`、`https`、`www`、`com` などのありふれた語は、候補から外す。
- 遮断用、例外用、`$important` 用、`$removeparam` 用で、索引を別々に持つ。

### 3.4 パターン照合

正規表現は使わず、専用の照合器を自作する。

- パターンを、「固定文字列、`*`、`^`、先頭固定 `|`、末尾固定 `|`、ホスト固定 `||`」の命令列にコンパイルしておく。
- `*` は、次の固定文字列を `memmem` で探してから先へ進む。戻ってやり直すのは、一致しなかった `*` の位置からだけにする（最悪でも O(n·m)）。
- `||` は、ホスト部分の中で、ドメインの区切り（先頭または `.` の直後）の位置にだけ一致させる。

### 3.5 オプションの評価

- 種類（ビットマスク）とサードパーティかどうかを、パターン照合の前に判定する（安い判定から先に行う）。
- `$domain=` は、ドメイン列（ハッシュの配列。`~` による否定の印付き）と、トップレベルのホスト名の各階層とを照合する。
- エンティティ指定（`example.*`）は、eTLD を除いた部分で照合する。

## 4. 要素の非表示

### 4.1 フィルタの分類

| 区分 | 例 | 格納方法 |
|---|---|---|
| 共通・単純 | `##.ad-box`、`###sidebar-ad` | class / id のハッシュ → セレクタのハッシュ表 |
| 共通・複雑 | `##div[class^="ad-"] > a` | 一番右の部分のキーを抽出できれば、上の表に入れる。抽出できなければ「常に適用」のリストへ（件数が少ないことを確認する） |
| サイト指定 | `example.com##.promo` | ホスト名の各階層とエンティティのハッシュ → セレクタ列 |
| 例外 | `example.com#@#.ad-box` | サイト指定と同じ形で、例外の印を付ける |
| HTML フィルタ | `example.com##^div.ad` | サイト指定と同じ形。ツリー構築のときに参照する |
| `:style()` | `example.com##.x:style(max-height:none)` | サイト指定と同じ形。宣言付きで保持する |

### 4.2 適用の手順（文書ごとに 1 回）

DOM は変化しないので、uBO のように DOM の変更を監視し続ける必要がない。

1. パースの開始時に、トップレベルのホスト名でサイト指定のフィルタ（HTML フィルタを含む）を引いておく。
2. パースの完了時（またはパース途中の区切りごと）に：
   - パース中に集めた **class / id のハッシュ集合**で、共通・単純の表を引く
   - 「常に適用」のリストと、サイト指定のフィルタを加える
   - 例外と、`$generichide` / `$elemhide` / `$specifichide` で除外する
   - 残ったセレクタから、`selector, selector, ... { display: none !important }` と `:style()` のルールを生成する
3. 生成したルールを、**user origin のスタイルシート**としてカスケードに加える（03 章 3.3 節）。

- セレクタの文字列は、filters.bin 内の文字列領域を直接参照し、コピーしない。
- 構文エラーのあるセレクタは、コンパイル時に CSS パーサで検証して捨てる。1 つの誤ったセレクタのせいで、ルール全体が無効になるのを防ぐため。

## 5. バイナリスナップショット（filters.bin）

```
ヘッダ
  magic "HKFLT\0", フォーマットのバージョン, エンジンのバージョン
  元にしたリストごとの (URL のハッシュ, 内容の SHA-256, 有効期限)
  各セクションの (オフセット, 長さ)
セクション
  STRPOOL     すべての文字列（パターン、セレクタ、ドメイン）。重複を除去済み
  HOSTSET_*   区分 A のハッシュ表（遮断、例外、important ごと）
  TOKIDX_*    区分 B のハッシュ表（トークン → FILTER の範囲）
  FILTERS     フィルタのレコード（固定長 16 バイト）
               u32 flags（種類のマスク、サードパーティ指定、important、例外、match-case）
               u32 パターンのオフセット（命令列）
               u32 オプションのオフセット（ドメイン列など。0 = なし）
               u32 元のリスト番号と行番号（ログ表示用）
  PATTERNS    コンパイル済みのパターン命令列
  DOMAINLISTS $domain= などのハッシュ配列
  COSM_*      要素非表示の各ハッシュ表
  REGEX       コンパイル済みの正規表現（9 節）
```

- 数値はすべてリトルエンディアンにする。オフセットはファイル先頭からの相対値なので、マップした位置に依存しない。
- ハッシュが衝突しうる箇所では、必ず元の文字列と比較して確かめる。
- 読み込み時にヘッダとセクションの範囲を検査する。壊れていたらテキストのリストから作り直す。

## 6. リストの管理

- **保存場所**：`%LOCALAPPDATA%\Hawk\filters\<名前>.txt`（元のテキスト）と、`filters.bin`。
- **更新**：各リストの `! Expires:` に従う（既定は 4 日。最短 1 日、最長 14 日）。
  - 更新は I/O スレッドで行い、条件付き GET（ETag）を使う。
  - 更新があった場合は、`filters.bin.new` をコンパイルしてから差し替える。
  - 現在のマッピングは、開いているタブがなくなるまで保持し、新しく始まるナビゲーションから新版を使う。
- **初回起動時**：ユーザーに確認してからダウンロードする。オフラインでも使えるよう、小さな最低限のリストを同梱する。同梱するのは、GPLv3 と両立するライセンスのリストに限る（README の D1）。
- **既定のリスト**（README の D3。配布前に各リストのライセンスを確認する）：EasyList、EasyPrivacy、uBlock filters（本体・privacy・unbreak）、AdGuard Japanese filter、Peter Lowe's list。
  - 任意で有効化できるもの：EasyList Cookie List（Cookie 同意バナー対策）、豆腐フィルタ、AdGuard URL Tracking Protection（`$removeparam` 用）。
- **自分のフィルタ**：`hawk:blocker` のページで、テキストエリアから編集する。

## 7. 内部ページ `hawk:blocker`

- 現在のタブのリクエスト一覧：URL、種類、判定結果、一致したフィルタと、その元のリスト・行番号。
- リストの有効・無効の切り替え、今すぐ更新、自分のフィルタの編集。
- サイトごとの無効化リスト。
- 統計：読み込んだフィルタの件数、捨てたフィルタの件数と理由、filters.bin のサイズ。

## 8. 性能目標

| 指標 | 目標 |
|---|---|
| 1 リクエストの判定 | 平均 2 µs 以下、99 パーセンタイルで 20 µs 以下 |
| filters.bin の実メモリ（既定のリストで） | 8 MB 以下（ページキャッシュとして共有され、実際に使われるのは一部） |
| コンパイル時間（既定のリストで） | 1 秒以下 |
| 起動時の読み込み | 1 ms 以下（マップするだけ） |
| 要素非表示ルールの生成 | 1 文書あたり 2 ms 以下 |

## 9. 正規表現エンジン（最小限）

- **対応する表現**：リテラル、`.`、文字クラス `[...]` と `[^...]`、`\d \w \s \D \W \S`、`^ $`、`* + ?`、`{n} {n,} {n,m}`（m ≤ 32）、`|`、グループ `( )`、`(?: )`、`\b`。
- **方式**：Thompson NFA（後戻りしない）。照合時間は入力長に比例するので、悪意のあるパターンでも遅くならない。
- **対応しない表現**：後方参照、先読み・後読み、`(?i)` 以外のフラグ。これらを含むフィルタは捨てて記録する。
- `$removeparam=/re/` も、同じエンジンで処理する。
